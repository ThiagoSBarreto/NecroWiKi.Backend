# NecroWiKi.Backend

NecroWiKi.Backend is the API and service layer that powers the NecroWiKi platform. It provides endpoints for user registration flows and for the arcade/game system features exposed to the Angular frontend.

## Project purpose

This backend is responsible for:

- handling account registration for supported communities such as WoW and Ragnarok;
- exposing game-system metadata and ROM/image resources;
- uploading and editing ROM and cover files in the game storage directory;
- listing and publishing Markdown tutorials with image and video media;
- providing a centralized API layer for the NecroWiKi frontend and related services.

## Architecture

The solution is organized in a layered ASP.NET Core structure:

```text
src/
  NecroWiKi.API/
    Controllers/         - HTTP endpoints for register and game-system APIs
    Program.cs           - API composition and dependency registration

  NecroWiKi.Application/
    Interfaces/          - application contracts
    Services/            - business services for registration and game systems
    Models/              - API and DTO models

  NecroWiKi.Infrastructure/
    - infrastructure and data-related support code
```

## Main endpoints

The main controllers expose the following routes:

- `POST /api/Register/wow`
- `POST /api/Register/ragnarok`
- `POST /api/auth/register` (public account, always role `User`)
- `POST /api/auth/login`
- `GET /api/auth/me` (authenticated)
- `GET /api/admin/accounts` (Admin)
- `POST /api/admin/accounts` (Admin)
- `PUT /api/admin/accounts/{id}` (Admin)
- `DELETE /api/admin/accounts/{id}` (Admin)
- `GET /api/GameSystem/{system}/roms`
- `GET /api/GameSystem/{system}/image/{fileName}`
- `GET /api/GameSystem/{system}/rom/{fileName}`
- `POST /api/GameSystem/{system}/upload`
- `PUT /api/GameSystem/{system}/roms/{currentName}`
- `GET /api/tutorials?category={category}&q={search}` (authenticated)
- `GET /api/tutorials/{slug}`
- `GET /api/tutorials/{slug}/images/{fileName}`
- `POST /api/tutorials` (authenticated; multipart form with `title`, `category`, `summary`, `markdownFile`, optional `videoUrl` and `images`)
- `PUT /api/tutorials/{slug}` (owner or Admin)
- `DELETE /api/tutorials/{slug}` (owner or Admin)

## Run locally

From the backend repository root:

```bash
dotnet restore
DOTNET_ENVIRONMENT=Development dotnet run --project src/NecroWiKi.API/NecroWiKi.API.csproj
```

The API will be available from the configured ASP.NET Core host, typically through the local development endpoint generated by the runtime.

## Portal authentication

Configure these environment variables before starting the API:

- `Authentication__JwtKey`: random signing key of at least 32 bytes;
- `PortalAdmin__UserName`: initial Admin username, 3-32 characters;
- `PortalAdmin__Password`: initial Admin password, at least 10 characters.

The bootstrap account is created only when the portal account table is empty. Public registration can create only `User` accounts. Do not commit real values; `.env.example` contains placeholders for Docker Compose.

The first authentication request creates the `PORTAL_ACCOUNTS` table if needed. You can also apply `database/PORTAL_ACCOUNTS.sql` manually; the script is idempotent. The database account needs `CREATE TABLE` permission only if relying on automatic creation. The JWT is checked against the current account status and role on each authenticated request, so disabling an account or changing its role invalidates existing tokens immediately. ROM catalog reads remain public for Guest arcade access; ROM writes require Admin. Save-state endpoints require a matching authenticated portal account ID.

## Configuration

The application reads endpoint and database configuration from the `appsettings.json` and `appsettings.Development.json` files, including:

- logger settings;
- connection strings for WoW and Ragnarok services;
- game settings and shared storage paths;
- tutorial storage path (`Tutorials:RootPath`, default `/games/TUTORIALS`).

## Docker Compose

The backend repository can be configured with a compose file like this:

```yaml
services:
  api:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: necro_wiki_api
    restart: unless-stopped
    ports:
      - "6018:8080"
    networks:
      - necro_network
    extra_hosts:
      - "host.docker.internal:host-gateway"
    volumes:
      - /path/to/Games:/games

networks:
  necro_network:
    external: true
```

The backend compose file should define:

- the API port (`6018:8080`);
- the container name (`necro_wiki_api`);
- the same Docker network used by the frontend (`necro_network`);
- the shared games folder mount (`/path/to/Games:/games`).

Before using Compose, copy `.env.example` to `.env` and replace the placeholders with a unique JWT signing key and initial Admin credentials.

The mounted games directory must follow the expected structure:

```text
/games/ROMS/
  GBA/
    images/
  SNES/
    images/
  PSX/
    images/
  N64/
    images/
```

That structure lets the API expose ROM and cover resources by system.

Tutorials are stored alongside the games directory so they persist through the existing `/games` volume:

```text
/games/TUTORIALS/{slug}/
  metadata.json
  index.md
  images/
```

Markdown image links are relative to the tutorial directory, for example `![Map](images/map.png)`. Uploaded images may be PNG, JPG, GIF, or WebP. The optional video URL must point directly to an MP4, WebM, or OGG file.

## Settings and database connections

The backend configuration should contain the connection strings used by the two supported game systems:

```json
{
  "ConnectionStrings": {
    "WoW": "Server=host.docker.internal;Port=3306;Database=acore_auth;User ID=acore;Password=acore;",
    "Ragnarok": "Server=mariadb_local;Port=3306;Database=ragnarok;User ID=ragnarok;Password=ragnarok;"
  }
}
```

These connection strings correspond to:

- WoW using an AzerothCore / PlayerBots-compatible authentication database;
- Ragnarok using a 2012 pre-renewal rAthena-compatible database structure.
